## 1. 무엇을 만드나

나폴레온 힐 『생각하라 그리고 부자가 되어라』의 흐름
**확고한 목적 → 계획 → 즉시 실행 → 끈기(점검과 재계획)** 을 매일 굴리는 **나 혼자 쓰는 앱**.

투자(자산제곱)는 독립된 앱이 아니다. 목적을 이루는 **수단 가운데 하나**로 이 안에 들어간다.

```
                       ┌──────────────────────────┐
                       │   🎯 확고한 목적 (금액·기한·대가) │  ← 4단계 코칭이 만든다
                       └────────────┬─────────────┘
          ┌──────────────┬──────────┴──────────┬──────────────────┐
          ▼              ▼                     ▼                  ▼
   💼 버는 돈        💳 쓰는 돈             📈 불리는 돈         📰 판단 재료
   (제안·부수입)      (카드·지출)            (자산제곱 투자)        (텔레그램·리포트)
          └──────────────┴──────────┬──────────┴──────────────────┘
                                    ▼
                    🧮 순자산 / 목표 진척 / 저축률
                                    ▼
             🔁 매일(문장 읽기·습관) · 매주(점검·재계획) · 매월(결산)
```

## 2. 모듈 (도메인)

| 모듈 | 책임 | 지금 상태 |
|---|---|---|
| **coach** 부자코치 | 4단계 코칭(진단→제안→계획→지속), 확고한 목적, 매일 문장·습관, 주간 점검 | 시제품 있음 (`richcoach/`, `views/coach·home·weekly`) |
| **ledger** 가계부 | 카드·계좌 거래 수집 → 파싱 → 분류 → 월 지출·저축률 | 없음 (신규) |
| **invest** 자산제곱 | 보유 종목, 시세·환율, 5존 판정, AI 포트폴리오 분석 | 기존 `app.py` 1,100줄 한 파일 → **재설계 대상** |
| **intel** 판단 재료 | 텔레그램 채널 메시지 + 기존 PDF 리포트 → 요약 → 전략 컨텍스트 | PDF 파이프라인만 있음 (`strategy/analyze_new_pdfs.py`) |
| **networth** 순자산 | 투자 + 예금·현금 + 기타 자산 − 부채 → 목표 진척 | 없음 (시제품에서 임시 계산만) |
| **notify** 알림 | 아침·저녁 문장, 습관 체크, 손절·익절 경보, 주간 점검 알림 | 없음 (신규) |

### 모듈 사이의 연결 (이 앱이 따로 쓰던 도구들과 다른 점)

- coach 3단계 **"쓸 수 있는 시간, 자금, 도구"** ← ledger의 월 잉여자금과 networth의 현재 자산이 자동으로 들어간다
- coach **"투자 자산의 몫"** → invest AI 분석에 목표로 전달된다 (무리한 수익률 가정 금지)
- intel 요약 → invest의 **전략 컨텍스트**(지금의 `current_strategy.md` 역할)
- ledger + invest → networth → 🏠 오늘 화면의 **목표 진척**
- 주간 점검 = 이번 주 행동 + 지출 + 자산 변화를 **한 번에** 본다 → 막혔으면 계획을 다시 세운다 (힐의 끈기)

## 3. 레이어

```
 수집(collectors)        저장(storage)         도메인(services)          화면/알림(apps)
 ─────────────────      ─────────────        ──────────────────        ────────────────
 telegram_channels ─┐                         coach   (4단계, 목적)      Streamlit 웹앱
 telegram_bot ──────┼──▶  raw_events  ──▶     ledger  (파싱·분류)   ──▶  텔레그램 봇 (푸시)
 card_sms(문자) ─────┤      (원본 보관)        invest  (시세·5존·AI)
 pdf_reports ───────┤                         intel   (요약·전략)
 market(시세·환율) ───┘      domain tables      networth(합산·진척)
                            (정제된 데이터)
                                   ▲
                                   └── Claude API (분석·추출·코칭): 한곳(ai/)에서만 호출
```

원칙
1. **수집과 해석을 나눈다.** 들어온 원문(문자, 텔레그램 메시지)은 `raw_events`에 그대로 보관한다. 파서가 바뀌어도 다시 처리할 수 있다.
2. **규칙은 순수 함수로 둔다.** 5존 판정, 카드 문자 파싱 같은 규칙은 화면이나 API에 묶지 않고 테스트로 고정한다.
3. **Claude 호출은 `ai/` 한 곳에서만 한다.** 모델과 비용을 한곳에서 관리한다.
4. **개인 데이터는 공개 저장소에 두지 않는다.** (5절 참고)

## 5. 데이터 저장과 실행 환경 — `[결정 필요]`

이 저장소는 `raw.githubusercontent.com`으로 인증 없이 읽히고 있다 → **공개 저장소일 가능성이 높다** `[확인 필요]`.
카드 내역과 자산 정보는 **공개 저장소에 절대 올리지 않는다.**

| 안 | 앱 실행 | 데이터 | 수집기(텔레그램·문자) | 장점 / 단점 |
|---|---|---|---|---|
| **A. 내 PC·맥 (또는 NAS) 상시 실행** | `streamlit run` 로컬 | 로컬 SQLite | 같은 기계에서 상시 실행 | 가장 단순하고 데이터가 밖으로 안 나감 / 밖에서 보려면 Tailscale 같은 터널 필요 |
| **B. 클라우드 앱 + 외부 DB** | Streamlit Cloud | Supabase(Postgres) 같은 무료 DB | 스케줄 작업(GitHub Actions cron 등) | 어디서나 접속 / 설정 단계가 많고, 저장소를 비공개로 바꿔야 함 |
| C. 혼합 | 로컬 | 로컬 SQLite + 주기 백업 | 로컬 | A와 같음, 백업만 추가 |

`[추론]` 나 혼자 쓰고 개인 금융 데이터를 다루므로 **A(또는 C)** 를 추천한다. 휴대폰에서는 텔레그램 봇으로 주로 보고, 웹앱은 집에서 연다.

## 6. 외부 데이터 연결 방법

### 6-1. 텔레그램 실시간 정보 (intel)
| 방법 | 읽을 수 있는 것 | 필요한 것 |
|---|---|---|
| **사용자 계정 API (Telethon 등)** | 내가 구독한 채널·그룹 메시지 전부 | my.telegram.org 에서 발급한 api_id/api_hash, 최초 1회 로그인, 상시(또는 주기) 실행 |
| 봇 API | 봇을 넣은 채널·그룹, 봇에게 보낸·전달한 메시지 | BotFather 토큰. 남이 운영하는 공개 채널에는 봇을 넣을 수 없는 경우가 대부분 `[확인 필요]` |

설계: 구독 채널 읽기는 **사용자 계정 API**로 하고, 알림 보내기와 내가 직접 전달하는 메시지 받기는 **봇**으로 한다.
수집한 메시지 → `raw_events` → 하루 단위 요약(intel digest) → 자산제곱 전략 컨텍스트와 주간 점검에 반영한다.
`[결정 필요]` 어떤 채널을 읽을지, 실시간 경보가 필요한지 하루 요약으로 충분한지.

### 6-2. 카드 사용 내역 (ledger)
| 경로 | 자동화 가능성 |
|---|---|
| **문자(SMS) 승인 알림** | iPhone: 단축어 '개인용 자동화 → 메시지 수신'으로 특정 키워드 문자를 봇이나 웹훅으로 보낼 수 있음 `[확인 필요: iOS 버전·확인 단계 여부]`. Android: 알림 전달 앱으로 가능 |
| **카카오톡 알림톡** | 카카오톡 메시지를 읽는 공식 API가 없다. iPhone에서는 자동 전달이 사실상 어렵다 `[확인 필요]` → ① 카드사 알림을 문자로 바꾸거나 ② 손으로 공유(봇에 전달)하거나 ③ 월말에 카드사 내역 파일을 올린다 |
| 카드사 내역 파일(엑셀·CSV) | 확실하지만 실시간이 아니다 (월 결산용 보완) |
| 마이데이터 | 개인이 직접 API로 쓰기는 어렵다 `[확인 필요]` |

설계: 어느 경로든 **텔레그램 봇이 받는 입구 하나**로 모은다. 들어온 원문은 카드사별 파서가 `{일시, 가맹점, 금액, 카드, 승인/취소}`로 바꾸고, 그다음 분류한다. 분류는 규칙을 먼저 쓰고, 규칙에 안 걸리는 것만 AI로 처리한다.
`[결정 필요]` 쓰는 카드사, 알림 방식(문자/알림톡), 휴대폰 기종.

### 6-3. 기존 PDF 리포트 파이프라인
지금은 Cowork 스케줄 태스크가 Obsidian 폴더의 PDF를 읽어 `current_strategy.md`를 만들고 GitHub에 push한다.
→ intel 모듈의 한 수집원으로 흡수한다. GitHub push 대신 DB에 저장하는 방식으로 바꿀지는 5절 결정에 따른다.

## 7. 자산제곱(invest) 재설계 방침

기존 기능은 **그대로 다 살린다**: 종목명 검색(네이버·Yahoo), 스크린샷 인식, 실시간 시세, 5존 판정, 52주 위치, TradingView 차트, AI 종합 분석, 전략 딥다이브, 환율.
바꾸는 것:
- 한 파일 1,100줄 → 4절의 `invest/` 하위 모듈로 나누고, 5존 규칙은 테스트로 고정한다
- 보유 종목을 **DB에 저장**한다 (지금은 새로고침하면 기본값으로 돌아감)
- 분석할 때마다 **스냅샷**을 남긴다 → 순자산 추이와 목표 진척
- 현금 비중을 슬라이더 대신 **실제 현금 잔고**로 계산한다 (networth와 연결)
- AI 분석에 **확고한 목적과 판단 재료 요약**을 함께 넣는다
- 모델 ID와 호출 방식은 `ai/client.py`로 통일한다 (지금 쓰는 `claude-sonnet-4-6`, `claude-haiku-4-5-20251001` 정리)

## 8. 진행 순서 (제안)

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| **P0 기반** | 폴더 구조, 설정·비밀, DB, `ai/client.py`, 테스트 틀 | 빈 앱이 뜨고 DB에 쓰기·읽기가 된다 |
| **P1 코칭** | 시제품을 새 구조로 옮김: 4단계, 오늘 화면, 주간 점검 | 4단계를 끝내면 오늘 화면에 목적·문장·습관이 나온다 |
| **P2 자산제곱** | 기존 기능을 모듈로 나눠 옮기고, 보유 종목 저장과 스냅샷 추가 | 기존 앱과 같은 입력에서 같은 5존 결과 (테스트) |
| **P3 알림 봇** | 텔레그램 봇: 아침·저녁 문장, 습관 체크, 손절·익절 경보 | 봇이 정해진 시간에 문장을 보내고 체크가 기록된다 |
| **P4 가계부** | 봇으로 들어온 카드 알림 파싱·분류, 월 지출·저축률 | 실제 카드 문자 10건 이상이 정확히 파싱된다 |
| **P5 판단 재료** | 텔레그램 채널 수집, 하루 요약, PDF 파이프라인 흡수 | 매일 요약이 생기고 자산제곱 분석에 들어간다 |
| **P6 순자산** | 투자 + 현금 + 기타 − 부채, 목표 진척과 추이 | 오늘 화면의 진척이 실제 잔고 기준으로 나온다 |

`[추론]` P3(봇)를 앞에 둔 이유: 힐의 '아침저녁으로 읽기'와 매일 습관은 웹앱보다 휴대폰 알림이 꾸준히 하기 쉽고, 봇은 P4·P5의 입구로도 다시 쓰인다.

## 9. 결정이 필요한 것

1. 실행 환경과 저장 위치: A(로컬) / B(클라우드+외부 DB) / C
2. 저장소 공개 여부: 공개라면 비공개로 바꿀지 (B를 고르면 필수)
3. 텔레그램: 읽을 채널 목록, 실시간 경보가 필요한지 하루 요약이면 되는지
4. 카드: 카드사, 알림 방식(문자/카카오 알림톡), 휴대폰 기종
5. 자산제곱 화면에서 지금 꼭 유지해야 하거나 버려도 되는 기능
